# 1.3.0 方块显示审计

本记录针对 Litematic Studio 1.3.0 与本地 Minecraft Java 1.21.11 原版客户端资源。检查使用官方注册表的完整方块清单，而不是仅按方块名称筛选“非完整方块”。这里的通过表示下述检查未发现异常，不表示所有外观已经与游戏逐像素一致。

## 覆盖与结果

| 检查 | 实际结果 |
| --- | --- |
| 官方注册表 | 1,166 种方块，29,671 个合法状态 |
| CPU 资源与几何审计 | 检查全部 29,671 个状态；`issueCounts` 为空 |
| 模型资源 | 2,132 个引用模型，5,806 个模型与旋转组合 |
| GPU 独立绘制 | 全部 29,671 个状态进入检查；`errors` 为空，`passed: true` |
| 核心测试 | 148 个通过，0 失败，0 跳过 |
| 水及含水状态专项 | 10,506 个状态通过；唯一无外露水面的 62 个状态均为双层台阶 |

核心测试数量来自本轮启用本地可选输入后的日志。水体专项也单独运行过；它已经包含在核心测试清单中，不应再次累加测试数量。上述结果不包含便携 EXE 验收结论。

CPU 结果按状态分类如下：

| 分类 | 状态数 | 含义 |
| --- | ---: | --- |
| `pass` | 26,740 | 资源、选模、几何及 UV 检查通过 |
| `approximation` | 2,826 | 使用有明确边界的特殊静态模型或近似表面 |
| `intentional-empty` | 93 | 空气、不可见方块、没有匹配部件的组合模型及合法空模型 |
| `unsupported` | 12 | 移动活塞；仅凭方块状态无法还原运动中的方块 |

**12 个移动活塞状态未接受显示正确性评估。** 它们需要运动相关的方块实体 NBT；本轮完整状态枚举不包含这些 NBT 组合。程序保留原始 NBT 供检查，不能将跳过动态部分解释为渲染正确。

## 检查方法

`scripts/audit-blocks.cjs` 可显式调用本地原版 `net.minecraft.data.Main --reports`，读取生成的 `reports/blocks.json`。这一步使用本机已安装的 Java 和游戏依赖，不联网，不启动游戏，也不修改游戏目录。应用正常运行时只读取资源，不执行该开发审计步骤。

CPU 审计分批检查每个合法状态的变体与组合模型选择、模型继承、材质引用、空模型分类、有限坐标、生成后的几何属性，以及旋转和 UV 锁定后的纹理坐标。零厚度元素的有效正反面与零面积边缘分别记录，避免把合法薄片误判为空模型。该轮未发现缺失模型、缺失材质、UV 越界或非有限几何。

所有匹配的加权随机模型候选均检查了资源引用、父模型、材质及 UV；不仅检查列表第一项。按各状态展开，共有 4,853 个未被当前稳定预览选中的候选，其中 21 个模型仅出现在非首项。**实际预览和本轮 GPU 检查使用确定性的第一候选，没有分别绘制每个加权候选。**

`tests/nonfull-gpu-smoke.cjs` 使用真实 Electron/Three.js 渲染器，分批加载资源，再将每个状态单独显示，从四个对角方向绘制并读取像素。它检查 WebGL 错误和意外空白；没有几何的状态只有在 CPU 清单中明确分类为空，或明确记录为未评估的移动活塞时才能放行。筛选结果为空不会被算作成功。

GPU 报告中，29,566 个应显示的状态都有几何并产生可见像素；93 个正常空模型状态中，有 43 个仍显示含水表面，50 个没有几何。加上 12 个未评估的移动活塞，共计 62 个零几何状态。这个“62”与水体专项的“62 个双层台阶”是不同统计，不能混用。

水体专项验证 10,506 个水、气泡柱及含水状态，涉及 8,557 种不同状态模型，累计生成 123,505 个水面。检查包括坐标范围、法线长度、UV 图集范围、索引与方块归属，以及意外空水体。62 个无外露水面的状态全部为完整双层台阶；其余被测水体状态均生成水面。这是静态模型占据近似检查，不是流体传播模拟。

报告另生成 15 张按方块类型汇集的代表图，本轮已逐张人工查看模型轮廓、面朝向与明显材质问题。代表图人工检查不能证明每个状态的每个 UV、全部观察角度或全部 NBT 外观组合正确；特殊近景仍需另行复核。部分特殊模型另以本地原版模型数值核对了顶点、UV 和绕序；原版导出网格不随仓库分发。

特殊近景复核发现双箱连接端的原版 UV 指向透明区域，仅保留该面的几何无法保证分离显示完整。预览使用同一半箱的外侧纹理封口；普通、陷阱及各种铜箱的 60 个封口经真实 PNG 像素检查均为不透明。原版外表面仍单独核对顶点、UV 和绕序，预览封口不冒充原版外表面。

本地客户端的头颅渲染器使用专用双面裁切材质；原始骷髅底面贴图本就存在透明像素。头颅按该规则显示孔隙后的内侧，普通方块保持单面，避免用全局双面掩盖模型问题。

## 已知边界

- 特殊模型采用静止姿态；不覆盖所有开盖、翻书、激活、动画及世界交互效果。
- 告示牌文字、旗帜与陶罐图案、自定义玩家头颅皮肤等 NBT 外观，没有通过完整组合枚举。
- 末地传送表面使用本地静态材质近似，没有复现原版视差着色器。
- 含水几何不模拟流向变化、完整流体规则或逐纹理孔隙的体素化；环境色也不代表所有生物群系和光照条件。
- CPU 检查不等同于原版截图对比；GPU 的非空像素检查也不能单独证明每个面和纹理细节正确。
- 本轮全量结果针对指定原版版本，不能自动推广到其他版本、模组方块或第三方资源包扩展。

## 复现

在项目根目录运行。将占位文件名替换为自己的本地客户端 JAR；首次安装项目依赖另需执行 `npm ci`。

```powershell
$env:MINECRAFT_JAR = "本地客户端.jar"

# 生成官方注册表并审计全部合法状态。
node scripts/audit-blocks.cjs --jar $env:MINECRAFT_JAR --generate-registry

$env:BLOCK_REGISTRY = "test-results/block-audit/vanilla-registry/reports/blocks.json"
$env:BLOCK_AUDIT_MANIFEST = "test-results/block-audit/manifest.json"
$env:MINECRAFT_REGISTRY = $env:BLOCK_REGISTRY
$env:MINECRAFT_BLOCK_REGISTRY = $env:BLOCK_REGISTRY

# 核心测试与单独的全量水体检查。
npm test
node --test tests/fluid-registry.test.cjs

# 真实显卡检查会启动测试应用，需要可运行 Electron 的桌面环境。
npm run build
node tests/nonfull-gpu-smoke.cjs
```

已生成注册表时，可复用它而不再次执行 Java：

```powershell
node scripts/audit-blocks.cjs --jar $env:MINECRAFT_JAR --registry $env:BLOCK_REGISTRY --out test-results/block-audit --batch-size 2048
```

只运行合成测试时不需要私人投影或原版导出数据。本轮完整核心测试还启用了本地可选输入：`LITEMATIC_SAMPLE`、`COPPER_MODEL_ORACLE`、`SPECIAL_MODEL_ORACLE`；未提供这些输入时，对应测试明确跳过，因此不能预期复现“148 个通过、0 跳过”的相同计数。原版模型对照输入应保留在本地，不提交到仓库。

不指定注册表时，CPU 脚本只枚举资源 JSON 可推导的可视属性组合，并将覆盖标记为 `inferred-visual-properties`；该模式不能用于声称完整合法状态覆盖。完整 GPU 检查也不应设置缩小范围的 `BLOCK_GPU_FILTER`。

本轮结果依据为 `test-results/block-audit/summary.json`、`test-results/block-audit/manifest.json`、`test-results/block-gpu/report.json`、`test-results/core-v130.log` 与 `test-results/fluid-v130.log`。这些本地报告、截图及资源对照文件被 Git 忽略，不作为仓库分发内容。
