# Litematic Studio

独立的 Windows x64 `.litematic` 3D 查看与方块替换工具。直接读取本机 Minecraft 的模型和贴图，支持分层观察、按方块及状态筛选、NBT 和容器检查、实体预览与材料导出。查看投影无需启动 Minecraft。

## 1.1.0 功能

- 玻璃、冰、水等透明面按视角排序，移除相邻同类透明方块之间的内部面；分层后重新显示切面。
- Blender 风格视图操作：中键旋转、Shift + 中键平移，支持透视和正交视图。
- 将一种或多种方块替换为目标方块，可作用于整个投影或当前可见部分，支持撤销、重做与另存。
- 筛选含水、可含水但未含水、通电、点亮、打开、流体、透明及其他常见特殊方块；也可直接筛选状态属性和值。
- 预览投影保存的实体，点选或通过列表定位并检查完整 NBT。
- 单层、连续高度范围、不连续多层与方块种类多选；材料 CSV、NBT JSON、视图 PNG 导出。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。

## 运行与材质

从 [GitHub Releases](https://github.com/novahanser/litematic-studio/releases/latest) 下载便携 EXE。1.1.0 的文件名为 `Litematic-Studio-1.1.0-win-x64.exe`，双击即可运行，无需额外安装 Java、Python 或 Node.js。自行构建后也可在 `dist/` 找到该文件，构建方法见下文。

点击「打开投影」、按 `Ctrl+O`，或将 `.litematic` 拖入窗口。也可把投影路径作为 EXE 的命令行参数。程序会记住最近的文件与材质设置。

首次运行会检测常见游戏目录，也可打开「材质」手动选择本地客户端 JAR。应选择含有 `assets/minecraft/blockstates`、`models`、`textures` 的完整游戏 JAR；Litematica 模组 JAR 不包含完整原版资源，不能替代它。材质版本应尽量与投影一致，开发时使用过 Minecraft Java 1.21.11 资源。

可叠加一个本地资源包 ZIP，覆盖同名模型和贴图；更改后点击「应用并重新加载当前投影」。中文名称优先从本地语言资源读取，缺失时显示英文或资源 ID。游戏客户端、资源包、贴图和私人测试投影均不随此仓库分发。

## 视图操作

| 操作 | 方法 |
| --- | --- |
| 旋转 | 中键拖动 |
| 平移 | `Shift` + 中键拖动 |
| 缩放 | 滚轮、`Ctrl` + 中键拖动，或界面的 `＋` / `−` |
| 选择方块或实体 | 左键单击 |
| 前 / 右 / 顶视 | 小键盘 `1` / `3` / `7`；自动切换为正交 |
| 后 / 左 / 底视 | `Ctrl` + 小键盘 `1` / `3` / `7` |
| 透视 / 正交 | 小键盘 `5`，或视图上方的投影按钮 |
| 聚焦所选对象 | 小键盘 `.` |
| 适应当前结构 | `Home`、`F`，或「适应视图」 |
| 键盘缩放 | `+` / `-` |

方向和缩放也有界面按钮。输入框或对话框正在使用时，视图快捷键不会抢占输入。工具栏提供网格开关与 PNG 截图导出。

## 分层、方块与状态筛选

「高度 / Y 层」支持全部、单层、范围和多选。多选可输入 `0, 3, 6-10`，也支持投影范围内的负坐标。范围包含起止两层。

「方块种类」支持中文或 ID 搜索、多种勾选、「仅此」「全选」「清空」。搜索只缩小列表；实际显隐由勾选状态决定。高度、种类、特殊状态、属性、NBT 与容器条件共同生效，可通过「重置」恢复全部方块。

含水筛选依据投影保存的 `waterlogged` 属性；「所有可含水方块」在当前投影中查找带该属性的状态，并非从游戏运行时推断。属性筛选可选择 `facing`、`half`、`waterlogged` 等键及其已出现的值。通电、点亮、打开等显示保存时的状态，不模拟红石变化。

实体跟随高度筛选，不跟随方块种类筛选；可在「实体」页关闭实体显示，或点击「隐藏方块」单独观察实体。

## 一键替换与保存

1. 点击「替换方块」，选择源方块，或选择「左侧勾选的所有方块种类」。
2. 选择「当前可见部分」或「整个投影」。前者包括当前层、种类、状态、NBT 和容器筛选结果。
3. 输入目标名称或资源 ID，选择目标状态。界面会先显示受影响方块数量。
4. 点击替换后检查预览，再用「另存投影」或 `Ctrl+S` 写出 `.litematic`。

「保留兼容的源状态」会把目标允许的源属性复制过去，覆盖上方目标属性选择；要强制设置目标属性，取消勾选它。例如把所有楼梯统一改为 `waterlogged=false` 时，应取消保留源状态。

同类型方块修改状态会保留 NBT；已识别的兼容方块实体家族也可保留 NBT。替换为不兼容类型时移除相应方块实体 NBT，包括原容器内容，避免把箱子的库存留在普通石头上。替换面板和结果会显示影响提示。

替换、撤销和重做先在内存中进行，不会自动写回输入文件。另存默认使用带 `_edited` 后缀的新名称，选择新文件名即可保留原文件。`Ctrl+Z` 撤销，`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做；历史最多保存 20 次，并受内存预算限制。切换文件或退出时，未保存的修改会提示处理。

替换会更新方块状态调色板和必要统计，保留未涉及的实体、区域及其他 NBT 数据。它不运行游戏邻居更新，不自动修正红石、流体或多格结构的连接关系。

## NBT、容器与实体

单击方块可查看坐标、状态属性、完整 NBT 和原始标签类型，并导出 JSON。64 位 `Long` 使用十进制字符串，避免精度损失。普通方块状态与方块实体 NBT 分开展示。

| 容器状态 | 含义 |
| --- | --- |
| 有物品 | 保存了有效物品记录，可查看槽位、名称和数量 |
| 已记录为空 | 明确保存了物品字段，但没有有效物品 |
| 未知 / 未记录 | 缺少 NBT 或物品字段，不能据此认为容器为空 |
| 待生成战利品 | 保存了战利品表，但没有生成后的物品清单 |

这里显示保存投影时的数据，不是服务器实时库存。末影箱玩家库存无法从方块 NBT 获取；模组自定义库存不保证自动识别，仍可检查原始 NBT。

实体页支持列表搜索、点选定位、NBT 和标签类型检查、JSON 导出。展示框显示朝向、旋转与内部物品；盔甲架、矿车、船及常见生物使用多部件静态近似模型，材质来自本地游戏。物品和方块展示实体支持基本变换；未知实体显示带名称的边界标记。当前不模拟动画、AI、乘客关系、完整装备外观或附魔光效，也不保证复现全部展示实体功能。

## 材料列表

可统计「整个投影」或「当前可见部分」，并导出 CSV。搜索用于界面查找，不缩减 CSV 的统计范围。不同朝向等状态合并；双层台阶按两个计，门、床按代表部分计件，红石线等换算为对应物品。容器内容与实体物品不混入建材。

这是建材估算。水、熔岩、火、活塞头等不计入普通材料；含水、盆栽、充能等可能需要的额外物品和施工流程不在估算中。「组」统一按 64 折算。仅显示门上半部等辅助部分时数量可能为零；多区域重叠按区域分别统计。

## 显示范围与限制

支持 Java 版 `.litematic`，不支持红石运行模拟或直接编辑游戏存档。大多数方块读取本地 JSON 模型，包括继承、组合模型、UV 和状态旋转。箱子、潜影盒、床、告示牌、旗帜、饰纹陶罐等依赖游戏特殊渲染的方块采用静态近似，未完整复现文字、图案、开盖或动态连接。

1.1.0 改进了透明面的排序和相邻面处理，但复杂相交的透明几何仍可能与游戏渲染不同。动画纹理使用静态帧；水和植被使用固定环境色，不模拟生物群系、光照传播、着色器或资源包专用渲染扩展。含水状态可筛选和编辑，预览不等同于完整流体模拟。缺失资源与近似模型可在「材质 → 本次读取提示」查看。

输入及解压后 NBT 限制为 512 MB，区域总体积限制为 33,554,432 个位置，后台处理超时为 120 秒。这些是保护性上限，不代表对应规模一定能流畅显示；性能还取决于模型复杂度、透明面数量和显卡。

程序在本地读取投影与资源，运行时不上传投影或下载材质。设置保存在应用用户数据目录；导出或另存由用户选择位置。仓库中的测试使用自行生成的合成数据，私人投影、原始 NBT 和本地验收产物不分发。

## 开发与测试

建议在 Windows 上使用 Node.js 24。使用便携 EXE 无需执行这些命令：

```powershell
npm ci
npm test
npm run build
npm start
npm run dist
```

`npm test` 运行解析、资源读取、编辑和渲染几何测试；`npm run build` 构建界面；`npm start` 启动开发版；`npm run dist` 输出 Windows x64 便携包。依赖版本锁定在 `package-lock.json`，首次安装需要网络。

真实游戏资源和投影是可选集成测试输入，通过 `MINECRAFT_JAR` 与 `LITEMATIC_SAMPLE` 环境变量指定自己的本地文件。未提供时，相应测试跳过，合成数据测试仍照常运行。资源集成测试面向现代 Java 版原版方块模型。

图形界面测试会启动应用，需要可运行 Electron 的 Windows 桌面环境，不包含在默认 CI 中：

| 命令 | 输入与检查范围 |
| --- | --- |
| `npm run test:app` | 至少一个非空气方块的投影。块数、层数、材料与库存期望从输入动态计算；缺少多层、多种方块或有物品容器时，明确跳过对应子项。检查加载、筛选、截图、点击、CSV 和异常文件恢复；有物品容器还会检查完整 NBT 导出。 |
| `npm run test:edit` | 投影需要至少两个 Y 层有石英块，并包含带 `facing`、`waterlogged` 等属性的方块。检查单层替换、撤销、重做、另存和原文件哈希；容器及含水编辑另用脚本生成的临时合成投影验证。 |
| `npm run test:renderer` | 投影需要普通冰块 `minecraft:ice`，以及至少一个可定位的实体；第一个实体应有有效位置，建议使用物品展示框。检查 Blender 操作、透明排序与实体点选，并输出近景截图。 |
| `npm run test:portable` | 先执行 `npm run dist`，再检查当前版本的 Windows 便携 EXE 是否能打开所提供的投影、读取本地材质与导出 PNG。 |

前三个命令会先构建界面。测试结果保存在不纳入 Git 的 `test-results/`；其中可能包含本地路径、截图和投影数据，请勿将私人运行产物直接提交。

GitHub Actions 在 Windows / Node.js 24 上执行依赖安装、核心测试和界面构建，不自动发布 EXE。核心测试与构建通过不等同于完成 GUI 或便携包运行验收。
